Subscription details

Immediate analyticsClient.logEvent(ScreenViewed(TRIP_DETAIL))

Fires synchronously before any coroutine is launched. Records that the Trip Detail screen was opened — not inside a coroutine or init block, so it captures the moment before any data loads.

Continuous observeStopsUseCase(tripId)

Re-runs on every stop change. Classifies the flat List<Stop> into the three UI roles based on order:

UiState fieldLogic
startingPointstop where order == 0
destinationstop with the highest order > 0
intermediateStopsstops between 0 and max order, sorted
canAddMoreStopsstops.size < 25
formattedStopCoordinatesMap<stopId, formatted lat/lon string>
Continuous observeLegsUseCase(tripId)

Re-runs on every route/leg change. Converts raw metres and seconds into locale-aware display strings for each leg.

UiState fieldLogic
legsraw list stored as-is
formattedLegDistancesMap<fromStopId, formatted string> via formatDistance(metres, locale, resources)
formattedLegDurationsMap<fromStopId, formatted string> via formatDuration(seconds, resources)
Continuous combine(stops, legs) branch

Re-runs when either stops or legs change. Drives the trip totals row and the route-recalculation prompt banner.

Route complete

Condition: legs.size == stops.size − 1 && stops.size ≥ 2

  • formattedTotalDistance — sum of all leg distances
  • formattedTotalDuration — sum of all leg durations
  • isRouteRecalculationPromptVisible = false
Route missing / stale

Everything else

  • formattedTotalDistance = null
  • formattedTotalDuration = null
  • isRouteRecalculationPromptVisible = stops.size ≥ 2
Continuous observeTripUseCase(tripId)

Observes the Trip entity. When trip != null, updates UiState.tripName. Used by the TopAppBar to show the real trip name while the screen loads (falls back to "Trip Detail" until the first emission).

One-shot combine(stops, legs).take(1)

Collects the very first combined emission of stops and legs, then cancels itself via .take(1). Logs TripOpened(stopCount, routeState) to analytics — not in the other combine subscription above, which would re-fire on every change. routeState is "complete" when the route is fully calculated, otherwise "none".

Design notes
  • All subscriptions share viewModelScope and are cancelled automatically when the ViewModel is cleared.
  • Stops and legs are subscribed twice each: once alone (for their own UiState fields) and once together in a combine (for totals and the analytics one-shot). This is intentional — each subscription is independent and does not interfere with the others.
  • Screen-view analytics is immediate, not deferred to a coroutine, consistent with the guideline that screen views come from navigation events, not ViewModel init. Here it approximates navigation because the ViewModel is created by navigation.
  • TripOpened analytics uses .take(1) so it only fires once per screen visit, not on every data change.
