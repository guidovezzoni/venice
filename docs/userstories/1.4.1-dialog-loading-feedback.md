# 1.4.1 — Dialog Loading Feedback

**Epic:** Trip Management
**Feature:** UI Feedback

## User Story

As a user, I want dialogs to show that a save is in progress so that I know my action is being processed and I don't accidentally tap confirm twice.

## Description

Both `TripDetailViewModel` and `TripListViewModel` already set `isLoading = true` before async operations and `false` on completion, but neither screen passes this state to its dialog composables. The confirm buttons remain enabled during the save, allowing double-submission.

This story wires `isLoading` through to all dialog composables so the confirm button is disabled while a save is in progress:

- **`SetStopDialog`** (used by starting point, destination, add stop, and edit stop dialogs)
- **`CreateTripDialog`** (used by the trip creation dialog)

### Gap in current change (1.2.5)

The `editStop()` function in `TripDetailViewModel` does not set `isLoading` at all, unlike the existing `setStop()` function. This should also be fixed.

## Acceptance Criteria

1. The confirm button in `SetStopDialog` is disabled while `isLoading` is `true`.
2. The confirm button in `CreateTripDialog` is disabled while `isLoading` is `true`.
3. The `editStop()` function in `TripDetailViewModel` sets `isLoading = true` before calling `EditStopUseCase` and `false` on success/failure.
4. All existing unit tests continue to pass.
5. Previews exist showing the loading state for both dialog composables.

## Technical Notes

- The OpenSpec main specs need updating: `destination-ui` (SetStopDialog), `trip-detail` (ViewModel loading behaviour, screen wiring), `trip-list` (TripListUiState `isLoading`), and `trip-creation` (CreateTripDialog).
- The `edit-intermediate-stop` delta spec should be updated to include `isLoading` in the `OnEditStopConfirmed` flow.
- No new string resources needed — the button text stays "Confirm", it's just disabled.
- `isLoading` is already declared in both `TripDetailUiState` and `TripListUiState` and already set in both ViewModels — only the UI wiring is missing.
