# 1.3.2 — See Which Stops Are Upcoming vs Completed

**Epic:** Trip Management
**Feature:** Stop Progress

## User Story

As a user, I want to see which stops are upcoming vs completed so that I can understand where I am in my roadtrip at a glance.

## Description

The trip detail screen visually distinguishes between stops already departed, the current stop, and upcoming stops. A progress summary gives the user an immediate sense of how far along the trip they are. This builds on the `StopStatus` field and `StopDisplayState` enum introduced in story 1.3.1.

## Current State Analysis

The 1.3.1 implementation already provides:
- `StopDisplayState` enum (`DEPARTED`, `CURRENT`, `UPCOMING`) derived from `StopStatus` and stop order
- `StopSection` composable applies `alpha = 0.6f` for departed stops and primary-colour icon tint for the current stop
- `deriveDisplayState()` function in `TripDetailScreen`

What is **missing** for this story:
1. **Stronger visual differentiation** — departed stops only fade; no checkmark or other visual indicator
2. **Current stop highlight** — only the icon is tinted; the stop card itself is not emphasised
3. **Trip progress summary** — no "X of Y stops completed" indicator anywhere on the screen

## Acceptance Criteria

- **AC-1**: Departed stops display a checkmark icon (replacing the default section icon) and use reduced opacity (`0.6f`).
- **AC-2**: The current stop card has a highlighted border (primary colour) to draw attention.
- **AC-3**: Upcoming stops are shown in their default style with no visual modification.
- **AC-4**: A progress summary (e.g., "3 of 6 stops completed") is displayed at the top of the trip detail screen when at least one stop exists.
- **AC-5**: When all stops are departed, the progress summary reflects completion (e.g., "6 of 6 stops completed").
- **AC-6**: When no stops have been departed, the progress summary shows "0 of N stops completed".

## Technical Design

### Data Layer
No data layer changes required. The `StopStatus` and `StopEntity` from 1.3.1 are sufficient.

### Domain Layer
No domain layer changes required. The existing `Stop` model and `StopStatus` enum provide all necessary data.

### UI Layer

#### 1. Progress Summary Composable

Create a new composable `TripProgressSummary` in `ui/screens/tripdetail/`:

- **Input**: `departedCount: Int`, `totalCount: Int`
- **Display**: Text like "3 of 6 stops completed" with a `LinearProgressIndicator` underneath
- **Visibility**: Only shown when `totalCount > 0`
- **Styling**: Use Material 3 `LinearProgressIndicator` with `MaterialTheme.colorScheme.primary`

#### 2. StopSection Enhancements

Modify `StopSection.kt` (`ui/screens/tripdetail/StopSection.kt`):

- **Departed state**: Replace the section icon with `Icons.Filled.CheckCircle` when `stopDisplayState == StopDisplayState.DEPARTED`
- **Current state**: Apply a `border` with `MaterialTheme.colorScheme.primary` colour (2.dp width) to the stop `Card`
- **Upcoming state**: No changes (keep current default styling)

#### 3. TripDetailScreen Integration

Modify `TripDetailScreen.kt` (`ui/screens/tripdetail/TripDetailScreen.kt`):

- Compute `departedCount` and `totalCount` from the stops list
- Add `TripProgressSummary` as the first item in the `LazyColumn`, before the starting point section

## Original User Story

### User Story

As a user, I want to see which stops are upcoming vs completed so that I can understand where I am in my roadtrip at a glance.

### Description

The trip view visually distinguishes between stops already visited, the current stop, and upcoming stops. This gives the user an immediate sense of progress.

### Acceptance Criteria

- Departed stops are visually distinct (e.g., greyed out, checkmark, strikethrough).
- The current stop is highlighted or emphasised.
- Upcoming stops are shown in their default style.
- The overall trip progress is clear at a glance (e.g., "3 of 6 stops completed").

### Technical Notes

- Derives directly from the `status` field on each `Stop` (see 1.3.1).
- Consider a progress indicator (e.g., a vertical timeline with filled/empty dots) that works well on both phone and, later, the constrained Android Auto templated UI.
