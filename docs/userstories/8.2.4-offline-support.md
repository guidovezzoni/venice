# 8.2.4 — Offline Support

**Epic:** Cloud Sync & Multi-User
**Feature:** Trip Sync

## User Story

As a user, I want to view and edit my trips even without an internet connection so that I can plan on the go.

## Description

If the offline+online architecture is chosen in story 8.1.1, this story implements the offline layer: Room remains the local source of truth, changes are queued when offline, and synced to Supabase when connectivity is restored. A conflict resolution strategy handles divergent edits.

## Acceptance Criteria

- The app is usable (view, create, edit trips and stops) without an internet connection.
- Changes made offline are queued and synced automatically when connectivity returns.
- Conflicts (e.g. the same trip edited on two devices while offline) are resolved according to the chosen strategy (last-write-wins, merge, or user prompt).
- The user is informed when operating in offline mode.
- Sync status is visible (e.g. pending changes indicator).

## Technical Notes

- **Conditional:** This story only applies if the 8.1.1 spike recommends offline+online. If online-only is chosen, this story is dropped.
- **Sync queue:** A local `pending_changes` table could track unsent mutations (insert, update, delete) with timestamps and retry logic.
- **Conflict resolution:** Last-write-wins (using `updatedAt` timestamps) is simplest. For stop ordering, a full-list replacement may be safer than per-stop diffs.
- **Connectivity:** Use Android's `ConnectivityManager` to detect network state and trigger sync.
