# 1.1.2 — See a List of My Roadtrips

## [original]

**Epic:** Trip Management
**Feature:** Trip CRUD

### User Story

As a user, I want to see a list of my roadtrips so that I can select one to view or edit.

### Description

A screen that lists all saved roadtrips. Each entry shows the trip name, number of stops, and total distance/duration if a route has been calculated. The list serves as the app's home screen.

### Acceptance Criteria

- All saved trips are displayed in a scrollable list.
- Each item shows at minimum: trip name, number of stops.
- If route has been calculated, also show total distance and estimated duration.
- Tapping a trip navigates to the trip detail/overview screen.
- Empty state is shown when no trips exist, with a prompt to create one.

### Technical Notes

- **Architecture:** Expose a `Flow<List<Trip>>` from the Repository so the list updates reactively when trips are added or modified.
- This screen will be the entry point of the app, replacing the current `Greeting("Android")` placeholder in `MainActivity`.

## [enhanced]

**Epic:** Trip Management
**Feature:** Trip CRUD
**Branch:** `feature/1.1.2-list-roadtrips`

### User Story

As a user, I want to see a list of my roadtrips so that I can tap on one to view or edit it.

### Context & Current State

The `TripListScreen` and its MVI stack already exist from story 1.1.1. The screen currently shows a list of trips and a FAB to create new ones, but:

- Trip list items display only a **name** — stop count is not shown.
- **Tapping a trip item does not navigate** anywhere (no `OnTripClicked` intent exists).
- **No empty state** is rendered when the trip list is empty.
- The `Trip` domain model has no `stopCount` field.

This story completes the list screen by wiring up item tap navigation, adding stop count to the item display, and implementing the empty state.

---

### Acceptance Criteria

- [ ] All saved trips are displayed in a scrollable `LazyColumn`, ordered by creation date descending.
- [ ] Each list item shows: **trip name** and **number of stops** (e.g. `"3 stops"` / `"0 stops"`).
- [ ] If a route has been calculated, the item also shows **total distance** and **estimated duration** — defer to a future story if route data is not yet available in the domain model.
- [ ] Tapping a trip item navigates to `TripDetailScreen` for that trip.
- [ ] When the trip list is empty, a full-screen **empty state** is shown with a message and a prompt to create the first trip.
- [ ] The list updates reactively (no manual refresh needed) when trips are created or modified.

### Data Layer Changes

**`data/database/dao/TripDao.kt`** — replace `observeAll()` with a query that counts stops per trip. Since the stops table does not exist yet, use a subquery that returns `0`:

```kotlin
@Query("""
    SELECT trips.*,
           (SELECT COUNT(*) FROM stops WHERE stops.trip_id = trips.id) AS stop_count
    FROM trips
    ORDER BY trips.created_at DESC
""")
fun observeAll(): Flow<List<TripWithStopCount>>
```

> Until `stops` table is added, keep the existing simple query and hardcode `stopCount = 0` in the mapper. Add a `// TODO 1.2.x` comment for the migration point.

**`data/database/mapper/TripMapper.kt`** — update `toDomain()`:

```kotlin
fun TripEntity.toDomain(): Trip = Trip(
    id = id,
    name = name,
    stopCount = 0,   // ← hardcoded until stops table exists (TODO 1.2.x)
    createdAt = createdAt,
    updatedAt = updatedAt,
)
```
