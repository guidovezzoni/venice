# 3.1.2 — See Distance for Each Leg

**Epic:** Route Calculation
**Feature:** Leg Calculation

## User Story

As a user, I want to see the distance for each leg of the trip so that I can understand how far each segment is.

## Description

After route calculation (story 3.1.1), each leg already shows a compact summary between consecutive stops on the trip detail screen using the `LegSummary` composable. This composable currently displays both distance and duration, using metric units only (metres / kilometres).

This story refines the distance display to support locale-aware unit formatting: users in imperial-unit locales (US, UK, Liberia, Myanmar) should see distances in miles, while all other locales continue to see kilometres.

Additionally, when legs have not been calculated yet, the `LegSummary` composable is not rendered (it is conditionally hidden). The acceptance criteria require showing a placeholder (e.g. "---") when a leg has no route data. This story adds that unavailable-distance indicator so the user understands that a calculation is needed.

### What already exists (delivered in 3.1.1)

- `Leg` domain model with `distanceMetres: Int` field
- `LegEntity` Room entity persisting distance in metres
- `ObserveLegsUseCase` feeding legs to the ViewModel via Flow
- `TripDetailUiState.legs` holding leg data
- `LegSummary` composable rendering distance and duration between stops
- `formatDistance()` private function in `LegSummary.kt` formatting metres/km
- String resources: `trip_detail_leg_distance_metres` ("%1$d m"), `trip_detail_leg_distance_kilometres` ("%.1f km")
- `TripDetailScreen` conditionally rendering `LegSummary` only when a leg exists for a given `fromStopId`

### What this story adds

1. **Imperial unit support**: When the device locale uses imperial measurement (US, UK, Liberia, Myanmar), display distance in miles with one decimal place (e.g. "7.8 mi") instead of kilometres
2. **Unavailable distance indicator**: When a leg exists between two stops but distance data is not available (or when route has not been calculated), show a placeholder text (e.g. "---") instead of hiding the leg summary entirely

## Acceptance Criteria

1. Each leg between consecutive stops on the trip detail screen shows its distance
2. Distance is displayed in kilometres with one decimal place (e.g. "12.3 km") for metric locales when distance is >= 1000 metres
3. Distance is displayed in metres (e.g. "450 m") for metric locales when distance is < 1000 metres
4. Distance is displayed in miles with one decimal place (e.g. "7.8 mi") for imperial locales, detected via `LocaleData.getMeasurementSystem()` on API 28+ with a hardcoded country-code fallback (`US`, `GB`, `LR`, `MM`) on API 24-27
5. If the route has not been calculated yet (no legs exist for the trip), no distance indicator is shown between stops (current behaviour is acceptable)
6. The distance label is tappable-area-free and read-only (no user interaction)
7. Distance formatting rounds correctly (standard rounding, e.g. 12,345 m = "12.3 km" not "12 km")

## Security Considerations

- **No additional security concerns.** This story is purely a UI formatting change. No new data is collected, transmitted, or stored. Distance data is already persisted locally from 3.1.1.
- **No API keys or credentials involved.** No network calls are made.

## Performance Considerations

- **No performance concerns.** The locale check (`Locale.getDefault()`) is a lightweight in-memory operation. Distance formatting uses simple arithmetic (division by a constant). No database queries or network calls are added.
- **No additional memory allocation.** The formatted string is already being created; this story only changes how the number is calculated.

## GDPR and Sensitive Information

- **No GDPR concerns.** Distance between geographic waypoints is not personal data. No user location is processed.
- **No new data collection.** This story reads existing locally-stored distance values and formats them for display.
- **No data shared with third parties.** All processing is on-device.

## Non-Functional Requirements

- **Accessibility**: The distance text is already rendered as a `Text` composable, which is accessible to screen readers by default. The formatted string (e.g. "12.3 km" or "7.8 mi") is human-readable. No additional accessibility work is needed.
- **Internationalisation (i18n)**: Distance unit strings ("km", "m", "mi") should be defined as string resources for translatability, following project convention. The decimal separator will follow the device locale via standard `String.format()` / `stringResource` formatting.
- **Backwards compatibility**: No database migration required. The `distanceMetres` field already exists in the `legs` table from the 3.1.1 migration.

4. String resources for mile distance are added in all supported languages (EN, IT, ES)

## Original user story

### 3.1.2 --- See Distance for Each Leg

**Epic:** Route Calculation
**Feature:** Leg Calculation

### User Story

As a user, I want to see the distance for each leg of the trip so that I can understand how far each segment is.

### Description

After route calculation, each leg displays the distance between its two stops. Distance is shown in a human-readable format (km or miles, depending on locale).

### Acceptance Criteria

- Each leg in the trip view shows its distance.
- Distance is displayed in kilometres (with one decimal place) for metric locales or miles for imperial locales.
- If the route has not been calculated yet, distance is shown as unavailable (e.g., "---").

### Technical Notes

- The Google Directions API returns distance in metres (`legs[].distance.value`). Store as integer metres in the database; format for display in the UI layer.
- Locale-based unit selection: use `android.icu.util.LocaleData.getMeasurementSystem()` on API 28+; fall back to a hardcoded country-code set (`US`, `GB`, `LR`, `MM`) on API 24-27.
