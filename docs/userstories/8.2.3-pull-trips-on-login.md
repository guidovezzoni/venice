# 8.2.3 — Pull Trips on Login

**Epic:** Cloud Sync & Multi-User
**Feature:** Trip Sync

## User Story

As a user, I want to see my trips when I log in on a new device so that I can pick up where I left off.

## Description

On login or app start (with a valid session), the app fetches the user's trips and stops from Supabase and makes them available in the UI. If offline+online mode is used, the fetched data populates the local Room cache. If online-only, the data is served directly from the network response.

## Acceptance Criteria

- After login, the user's trips and their stops are fetched from Supabase.
- The trip list screen shows all cloud-stored trips.
- Opening a trip shows its stops with correct ordering and status.
- A loading indicator is shown while data is being fetched.
- Network errors are handled with a retry option or appropriate message.

## Technical Notes

- **Blocked by:** Story 8.1.1 (offline vs online decision).
- **Query:** `supabase.postgrest["trips"].select { filter { eq("user_id", userId) } }` with a similar query for stops.
- **Initial sync:** On first login on a new device, all data must be pulled. Subsequent launches may use incremental sync or cache invalidation depending on the chosen architecture.
