# 8.1.6 — Auth State Management

**Epic:** Cloud Sync & Multi-User
**Feature:** Backend Foundation & Auth

## User Story

As a user, I want the app to remember my login and take me straight to my trips so that I don't have to log in every time.

## Description

The app checks authentication state on launch and routes accordingly: authenticated users go directly to the home screen, unauthenticated users see the login screen. A splash screen is shown briefly while the auth state is being resolved. Expired or revoked tokens are handled gracefully by redirecting to login.

## Acceptance Criteria

- On app launch, a splash screen is shown while the auth state is determined.
- If the user has a valid session, they are navigated to the home screen.
- If there is no session or the session is expired/revoked, the user is navigated to the login screen.
- Token expiry during app use redirects the user to the login screen with an appropriate message.
- The auth gate is implemented at the navigation level so that authenticated screens are not accessible without a session.

## Technical Notes

- **Supabase session status:** Use `supabase.gotrue.sessionStatus` (a `StateFlow`) to observe auth state reactively.
- **Navigation:** Consider a sealed `AuthState` (Loading, Authenticated, Unauthenticated) that drives a `NavHost` split between auth and main navigation graphs.
- **Token events:** Listen for `SessionStatus.NotAuthenticated` to handle token revocation mid-session.
