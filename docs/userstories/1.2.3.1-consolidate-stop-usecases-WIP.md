# 1.2.3.1 — Consolidate Stop Use Cases

**Epic:** Trip Management
**Feature:** Stop Management

## User Story

As a developer, I want the three stop use cases (`SetStartingPointUseCase`, `SetDestinationUseCase`, `AddIntermediateStopUseCase`) consolidated into a single `SetStopUseCase` with a `StopType` discriminator, so that the domain layer is simpler and easier to maintain.

## Description

The three use cases share the same signature `(tripId, placeName, latitude, longitude) -> Result<Stop>` and all trim the place name before delegating to a repository method. A `StopType` enum (`STARTING_POINT`, `DESTINATION`, `INTERMEDIATE`) is introduced to distinguish the operation. The consolidated use case delegates to the appropriate repository method based on the stop type. The `TripDetailViewModel` is updated to inject a single use case instead of three.

The repository layer is intentionally left unchanged — the three repository methods (`upsertStartingPoint`, `upsertDestination`, `addIntermediateStop`) have genuinely different data-layer behaviour.

## Acceptance Criteria

- A `StopType` enum exists in the domain model with entries: `STARTING_POINT`, `DESTINATION`, `INTERMEDIATE`.
- A single `SetStopUseCase` replaces `SetStartingPointUseCase`, `SetDestinationUseCase`, and `AddIntermediateStopUseCase`.
- `SetStopUseCase` trims the place name for all stop types.
- `SetStopUseCase` enforces the 25-stop limit only for `INTERMEDIATE` stops.
- `SetStopUseCase` delegates to the correct repository method based on `StopType`.
- `TripDetailViewModel` injects and uses only `SetStopUseCase`.
- The three old use case files and their test files are deleted.
- A single `SetStopUseCaseTest` covers all stop types.
- `TripDetailViewModelTest` is updated to mock the single use case.
- All existing tests pass. `./gradlew check` passes.
- No references to the old use case class names remain in `app/src/`.

## Technical Notes

- The `StopRepository` interface and `StopRepositoryImpl` are not modified — the three repository methods remain distinct.
- No UI changes are required — `TripDetailUiState`, `TripDetailUiIntent`, `TripDetailUiEffect`, and `TripDetailScreen` are unaffected.
- Hilt auto-discovers `SetStopUseCase` via its `@Inject` constructor; no DI module changes needed.

## Detailed Technical Specification

### 1. New files to create

#### `StopType.kt`
- **Path:** `app/src/main/java/com/guidovezzoni/venice/domain/model/StopType.kt`
- **Content:** An enum class with entries `STARTING_POINT`, `DESTINATION`, `INTERMEDIATE`
- Follows the same pattern as the existing `StopStatus` enum in the domain model package

#### `SetStopUseCase.kt`
- **Path:** `app/src/main/java/com/guidovezzoni/venice/domain/usecase/SetStopUseCase.kt`
- **Dependencies:** `StopRepository` (injected via `@Inject constructor`)
- **Signature:** `suspend operator fun invoke(tripId: String, placeName: String, latitude: Double, longitude: Double, stopType: StopType): Result<Stop>`
- **Behaviour:**
  1. Trims `placeName` for all stop types
  2. When `stopType == INTERMEDIATE`: checks `stopRepository.getStopCount(tripId)` and returns `Result.failure(IllegalStateException("Maximum of 25 stops reached"))` if count >= 25
  3. Delegates to the correct repository method via a `when` on `stopType`:
     - `STARTING_POINT` → `stopRepository.upsertStartingPoint(tripId, trimmedName, latitude, longitude)`
     - `DESTINATION` → `stopRepository.upsertDestination(tripId, trimmedName, latitude, longitude)`
     - `INTERMEDIATE` → `stopRepository.addIntermediateStop(tripId, trimmedName, latitude, longitude)`
- **Constant:** Extract `MAX_STOP_COUNT = 25` as a private file-level constant

#### `SetStopUseCaseTest.kt`
- **Path:** `app/src/test/java/com/guidovezzoni/venice/domain/usecase/SetStopUseCaseTest.kt`
- **Test cases (GIVEN/WHEN/THEN naming):**
  - `GIVEN a valid starting point WHEN invoke is called THEN repository upsertStartingPoint is called with trimmed name`
  - `GIVEN a valid destination WHEN invoke is called THEN repository upsertDestination is called with trimmed name`
  - `GIVEN a valid intermediate stop WHEN invoke is called THEN repository addIntermediateStop is called with trimmed name`
  - `GIVEN stop count below limit WHEN adding intermediate stop THEN result is success`
  - `GIVEN stop count at limit WHEN adding intermediate stop THEN result is failure with IllegalStateException`
  - `GIVEN repository returns failure for starting point WHEN invoke is called THEN failure is propagated`
  - `GIVEN repository returns failure for destination WHEN invoke is called THEN failure is propagated`
  - `GIVEN repository returns failure for intermediate stop WHEN invoke is called THEN failure is propagated`
  - `GIVEN place name with whitespace WHEN invoke is called for each stop type THEN name is trimmed`
- Use `@MockK` for `StopRepository`, `runTest`, and `coEvery`/`coVerify` from MockK

### 2. Files to modify

#### `TripDetailViewModel.kt`
- **Path:** `app/src/main/java/com/guidovezzoni/venice/ui/viewmodel/TripDetailViewModel.kt`
- **Changes:**
  - Replace imports of `SetStartingPointUseCase`, `SetDestinationUseCase`, `AddIntermediateStopUseCase` with imports of `SetStopUseCase` and `StopType`
  - Replace the three constructor parameters with a single `private val setStopUseCase: SetStopUseCase`
  - Refactor `setStartingPoint()`, `setDestination()`, and `addIntermediateStop()` private methods into a single `private fun setStop(placeName: String, latitude: Double, longitude: Double, stopType: StopType, dismissDialog: (TripDetailUiState) -> TripDetailUiState)` method that:
    1. Sets `isLoading = true`
    2. Calls `setStopUseCase(tripId, placeName, latitude, longitude, stopType)`
    3. On success: sets `isLoading = false` and applies the `dismissDialog` lambda to clear the relevant dialog flag
    4. On failure: sets `isLoading = false` and emits `ShowError` effect
  - Update `onIntent()` handler to call `setStop(...)` with the appropriate `StopType` and dialog-dismiss lambda:
    - `OnStartingPointConfirmed` → `StopType.STARTING_POINT`, dismiss `isSetStartingPointDialogVisible`
    - `OnDestinationConfirmed` → `StopType.DESTINATION`, dismiss `isSetDestinationDialogVisible`
    - `OnAddStopConfirmed` → `StopType.INTERMEDIATE`, dismiss `isAddStopDialogVisible`

#### `TripDetailViewModelTest.kt`
- **Path:** `app/src/test/java/com/guidovezzoni/venice/ui/viewmodel/TripDetailViewModelTest.kt`
- **Changes:**
  - Replace mocks of `SetStartingPointUseCase`, `SetDestinationUseCase`, `AddIntermediateStopUseCase` with a single mock of `SetStopUseCase`
  - Update all `coEvery` stubs to use `setStopUseCase(any(), any(), any(), any(), any())` or specific `StopType` matchers
  - Update all `coVerify` assertions to verify `setStopUseCase` invocations with the expected `StopType` argument
  - No changes to the dialog visibility tests or stop observation tests — those don't touch use cases directly

- Remove the TODO comments in the old use case files (they are deleted)

### 8. Security, Performance, GDPR, and Non-Functional Considerations

- **Security:** No security impact — this is a pure internal refactor with no changes to data handling, user input validation, or authentication. Place name trimming (the only input sanitisation) is preserved.
- **Performance:** No performance impact — the number of repository calls and coroutine scopes remains identical. The `getStopCount` call is only made for `INTERMEDIATE` stops, as before.
- **GDPR / Sensitive data:** No change to data storage, processing, or exposure. No new personal data is collected or logged.
- **Non-functional:** Reduces code duplication (3 classes → 1), improving maintainability. The `MAX_STOP_COUNT` constant is now defined in a single location instead of two (use case and ViewModel).
