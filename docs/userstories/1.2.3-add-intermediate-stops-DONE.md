# 1.2.3 — Add Intermediate Stops

**Epic:** Trip Management
**Feature:** Stop Management

## User Story

As a user, I want to add intermediate stops to my roadtrip so that I can plan breaks, visits, and detours along the way.

## Description

The user can add stops between the starting point and destination. Each stop is entered via a place-name / coordinate dialog (the same `SetStopDialog` pattern already used for starting point and destination) and inserted at a chosen position in the stop order. The existing stops shift their order to accommodate the new stop, and the destination always remains last. A maximum of 23 intermediate stops is enforced (25 total including start and destination — Google Directions API waypoint limit).

## Acceptance Criteria

- The user can add a new stop between any two existing stops.
- The stop is entered with place name, latitude, and longitude (reusing the existing `SetStopDialog`).
- The order of existing stops adjusts (shifts up) to accommodate the new stop.
- The destination always remains the last stop.
- The user can add up to 23 intermediate stops. When the limit is reached, the "Add Stop" button is hidden or disabled.
- Intermediate stops appear in the trip detail screen between the starting point and the destination, in the correct order.

## Fields

| Field       | Type     | Constraints                            |
|-------------|----------|----------------------------------------|
| `id`        | String   | UUID, auto-generated                   |
| `tripId`    | String   | FK to trips table                      |
| `placeName` | String   | Required, non-blank                    |
| `latitude`  | Double   | Required, range -90..90                |
| `longitude` | Double   | Required, range -180..180              |
| `order`     | Int      | ≥1, <destination order                 |
| `status`    | String   | Default: `PENDING`                     |

No new database columns are required — the existing `stops` table schema already supports arbitrary order values.

## Endpoints / APIs

No external API calls are required for this story. All operations are local Room database operations.

## Security Considerations

- **Input validation**: Place name, latitude, and longitude are validated both in the dialog (UI-level) and in the use case (domain-level) to prevent invalid data reaching the database. This mirrors the existing pattern in `SetStopDialog`.
- **SQL injection**: Not applicable — Room uses parameterised queries.
- **No user-generated content is rendered as HTML or interpreted** — Compose renders text as plain strings.

## Performance Considerations

- **Order shifting**: The `incrementOrderFrom` DAO query updates multiple rows in a single SQL `UPDATE` statement, which is efficient. With a maximum of 25 stops per trip, the operation is negligible.
- **Reactive observation**: The existing `observeByTripId` Flow already covers all stops; no additional queries are needed.
- **Transaction safety**: The shift + insert operation is wrapped in a `@Transaction` to prevent inconsistent ordering if the operation is interrupted.

## GDPR & Sensitive Information

- **Location data**: Latitude and longitude coordinates are stored locally in the Room database on the user's device. No data is transmitted externally in this story.
- **No personal data**: Place names are user-provided labels, not personal identifiers.

## Other Non-Functional Requirements

- **Accessibility**: The "Add Stop" button must have a content description for screen readers.
- **Configuration changes**: Dialog state is held in the ViewModel's `StateFlow`, which survives configuration changes.
- **Offline**: All operations are local — no network dependency.

## Original User Story

### 1.2.3 — Add Intermediate Stops

**Epic:** Trip Management
**Feature:** Stop Management

### User Story

As a user, I want to add intermediate stops to my roadtrip so that I can plan breaks, visits, and detours along the way.

### Description

The user can add stops between the starting point and destination. Each stop is selected via place search and inserted at a specific position in the stop order. Roadtrips are fundamentally about the stops along the way, so this is a core interaction.

### Acceptance Criteria

- The user can add a new stop between any two existing stops.
- The stop is selected via place search and stored with name, latitude, and longitude.
- The order of existing stops adjusts to accommodate the new stop.
- The destination always remains the last stop.
- The user can add up to 23 intermediate stops (25 total including start and destination — Google Directions API waypoint limit).

### Technical Notes

- Google Directions API supports up to 25 waypoints per request. This includes origin and destination, leaving room for 23 intermediate stops. Enforce this limit in the UI.
- After adding a stop, any previously calculated legs are invalidated and should be recalculated (see 3.1.1).
