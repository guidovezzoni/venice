# 8.2.1 — Sync Trips to Cloud

**Epic:** Cloud Sync & Multi-User
**Feature:** Trip Sync

## User Story

As a user, I want my trips to be saved to the cloud when I create or update them so that they are not lost if I lose my device.

## Description

When a trip is created or updated, the change is pushed to Supabase. The exact mechanism (direct write, sync queue, or dual-write) depends on the architectural decision made in story 8.1.1. The user's `user_id` is attached to each trip for ownership.

## Acceptance Criteria

- Creating a trip persists it to the Supabase `trips` table.
- Updating a trip name syncs the change to Supabase.
- Each trip is associated with the authenticated user's ID.
- Sync failures are handled gracefully (retry, user notification, or queued for later depending on architecture).

## Technical Notes

- **Blocked by:** Story 8.1.1 (offline vs online decision) determines the sync approach.
- **Supabase PostgREST:** Use `supabase.postgrest["trips"].insert(...)` / `.update(...)`.
- **ID strategy:** The app currently generates UUIDs locally. These can be used as the Supabase primary key directly, avoiding ID conflicts.
