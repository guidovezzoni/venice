# 8.2.2 — Sync Stops to Cloud

**Epic:** Cloud Sync & Multi-User
**Feature:** Trip Sync

## User Story

As a user, I want my stops to be saved to the cloud so that my full trip plan is backed up and accessible from anywhere.

## Description

When stops are added, updated, reordered, or deleted, the changes are synced to the Supabase `stops` table. Stop ordering and status must be preserved accurately. The sync approach follows the same pattern established in story 8.2.1.

## Acceptance Criteria

- Adding, updating, and deleting stops syncs the changes to Supabase.
- Stop ordering (`order` field) is preserved in the cloud.
- Stop status (PENDING, DEPARTED, etc.) is synced.
- Reordering stops updates the cloud records correctly.
- Sync failures are handled consistently with the trip sync approach.

## Technical Notes

- **Blocked by:** Story 8.1.1 (offline vs online decision).
- **Ordering:** The `order` field is an integer managed by transaction-safe bulk operations locally. The cloud sync must maintain consistency — consider syncing the full ordered list rather than individual order updates.
- **Cascade:** Supabase foreign key with CASCADE delete should mirror the Room setup so deleting a trip removes its stops.
