# 9.1.4 — Hilt Instrumented Test Infrastructure

**Epic:** Analytics
**Feature:** Analytics Foundation
**Status:** Backlog

## User Story

As a developer, I want Hilt dependency injection working in instrumented tests, so that I can replace
real analytics providers with recording fakes and assert on events, user properties, and exceptions
in Compose UI tests.

## Description

The project currently has no Hilt instrumented-test infrastructure. `HiltTestRunner` does not use
`HiltTestApplication`, there is no `hilt-android-testing` dependency, no `kspAndroidTest` processor,
and no `@HiltAndroidTest` consumer exists. All current Compose UI tests pass state directly without DI.

This story stands up the infrastructure and provides a `@TestInstallIn` module with a recording fake
that replaces the real analytics provider set in instrumented tests. The fake records events, user
properties, and exceptions for assertion.

### What changes

1. Add `hilt-android-testing` and `hilt-android-compiler` (KSP) dependencies for the `androidTest`
   configuration.
2. Fix `HiltTestRunner` to instantiate `HiltTestApplication`.
3. Create a `@TestInstallIn` module (`FakeAnalyticsModule`) that replaces `AnalyticsModule` (and
   `DebugAnalyticsModule`) with a recording fake.
4. The recording fake captures events, user properties, and exceptions in lists for assertion.

## Origin

Deferred from story 9.1.1 (AC 11) during the propose-change phase. The infrastructure effort was
materially larger than the single module file implied by the original acceptance criterion.
