# 8.1.2 — Supabase Project Setup

**Epic:** Cloud Sync & Multi-User
**Feature:** Backend Foundation & Auth

## User Story

As a developer, I want the Supabase project configured with the remote schema and Android SDK integrated so that subsequent stories can build on a working backend connection.

## Description

Set up the Supabase project (or connect to an existing one), define the database tables for trips, stops, and user profiles, configure Row Level Security policies, and add the Supabase Kotlin SDK to the Android project. This is the foundational infrastructure story.

## Acceptance Criteria

- A Supabase project exists with `trips`, `stops`, and `profiles` tables matching the current domain model.
- Row Level Security is enabled on all tables, with policies restricting access to the owning user.
- The Supabase Kotlin SDK is added to the project dependencies.
- A Supabase client is initialised in the app (via Hilt module) with the project URL and anon key.
- The anon key and URL are stored securely (not hardcoded in source — use `local.properties` or BuildConfig).

## Technical Notes

- **Remote schema:** The `trips` and `stops` tables should mirror the current Room entities, with an additional `user_id` column (FK to `auth.users`) for ownership.
- **RLS policies:** Each table needs at minimum: SELECT, INSERT, UPDATE, DELETE policies filtered by `auth.uid() = user_id`.
- **SDK:** `io.github.jan-tennert.supabase:postgrest-kt`, `gotrue-kt`, and `realtime-kt` are the relevant modules.
- **Profiles table:** A `profiles` table (id, email, display_name) linked to `auth.users` via trigger is standard Supabase practice.
