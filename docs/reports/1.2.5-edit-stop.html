User Story

1.2.5 — Edit a Stop: As a user, I want to edit a stop in my roadtrip so that I can correct or change a location.

Branch

Created branch feature/1.2.5-edit-stop from main.

Refinement Summary

  • Starting point and destination editing already works via the existing upsert flow — no changes needed for those stop types.
  • The gap is intermediate stops: tapping a filled intermediate stop card currently has no effect.
  • New EditStopUseCase and StopRepository.updateStop() method needed to update an intermediate stop by ID without changing its order.
  • UI changes: new edit intents, state fields (editingStop, isEditStopDialogVisible), and a dialog block in TripDetailScreen reusing SetStopDialog.
  • Leg invalidation (acceptance criterion 5) is a documented no-op — leg calculation is not yet implemented (Epic 3).

Change Proposed

28 May 2026

Source: sdlc_propose

Exploration Findings

  • Starting point and destination edit flows work end-to-end via SetStopUseCase → upsertStartingPoint/upsertDestination → StopDao.update().
  • Intermediate stop StopSection in TripDetailScreen does not pass an onSetStopClicked callback — tapping is a no-op.
  • The existing addIntermediateStop path only handles insertion, not updates.
  • SetStopDialog already supports pre-population via initialPlaceName, initialLatitude, initialLongitude params — fully reusable for editing.

Key Design Decisions

  • New EditStopUseCase rather than extending SetStopUseCase — clean separation between "add new" and "edit existing".
  • ID-based repository update: updateStop(stopId, …) fetches by primary key, preserving identity fields.
  • Reuse SetStopDialog: same composable, different title string, pre-populated initial values.
  • Leg invalidation: TODO marker in EditStopUseCase for Epic 3.
