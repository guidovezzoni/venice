User Story

1.2.6 — Remove a Stop: As a user, I want to remove a stop from my roadtrip so that I can simplify my journey or correct a mistake.

Branch

feature/1.2.6-remove-stop created from main.

Refinement Summary

The original user story was enriched with full technical detail covering all architecture layers:

  • Data layer: New StopDao methods (deleteById, decrementOrderAbove, deleteAndReorder) for atomic delete-and-reorder within a @Transaction.
  • Domain layer: New deleteStop method on StopRepository interface, implemented in StopRepositoryImpl. New RemoveStopUseCase with a TODO for leg invalidation (deferred to Epic 3).
  • UI layer: Three new MVI intents (OnRemoveStopClicked, OnRemoveStopConfirmed, OnDismissRemoveStopDialog), two new state fields (isRemoveStopDialogVisible, stopToRemove), a delete button on StopSection, and a confirmation AlertDialog on TripDetailScreen.
  • Strings: Five new string resources in EN, IT, and ES.
  • Tests: New RemoveStopUseCaseTest, plus additions to StopRepositoryImplTest and TripDetailViewModelTest.

Promotion rules for starting point/destination removal are handled by the reorder logic: after deleting any stop and decrementing orders above it, the stop at order 0 naturally becomes the starting point and the highest-order stop becomes the destination.

Change Proposed

30 May 2026

Source: sdlc_propose

Exploration

Investigated the existing codebase across all architecture layers to confirm the feature maps cleanly onto established patterns:

  • DAO: Existing @Transaction methods (shiftAndInsertStop, swapStopOrders) provide the template for deleteAndReorder. Existing getStopById and incrementOrderFrom queries confirm the order-manipulation pattern.
  • Repository: All mutations use runCatching for the Result pattern. deleteStop follows suit.
  • Use case: MoveStopUseCase (pass-through to repository) is the direct template. EditStopUseCase shows the TODO pattern for leg invalidation.
  • MVI: The three-intent dialog pattern (Clicked/Confirmed/Dismissed) is repeated for starting point, destination, add stop, and edit stop. Remove follows identically.
  • UI: StopSection already accepts optional action lambdas (onMoveUp, onMoveDown). Adding onDelete follows the same pattern.
