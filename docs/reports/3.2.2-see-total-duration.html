  • Listed files to modify with intent: UiState, ViewModel (extend existing combine block), TripTotalSummary composable, TripDetailScreen, string resources across 3 locales
  • Defined unit and Compose UI test expectations following GIVEN/WHEN/THEN naming
  • Scoped out trip-list total and "time at stop" to separate future stories

Key Concerns

  • Low Security: No new attack surface; only concern is integer summation integrity (mitigated by Long accumulation)
  • Low Performance: Negligible — summation over at most 24 legs reuses existing combine block
  • None GDPR: No personal data processed or created; no new data collection or transmission

Exploration Findings

  • Near-identical shape to archived story 3.2.1 (total distance) — same integration points, same completeness rule
  • TripDetailUiState already has formattedTotalDistance: String? — new field formattedTotalDuration: String? follows same pattern
  • Existing combine(observeStopsUseCase, observeLegsUseCase) collector (added by 3.2.1) can be extended rather than adding a 4th subscription
  • DurationFormatter.formatDuration already exists and is reused as-is
  • TripTotalSummary.kt composable needs restructuring from single-value Column to side-by-side Row layout
  • Analytics infrastructure exists (AnalyticsTracker/AnalyticsEvent) but no existing event tracks derived summary display

Questions Asked and Answers

  • Label text: "Est. driving time" / "Est. driving time unavailable"
  • Layout: Side by side (distance and duration in a Row, each taking half width)
  • Unavailable state: Single combined "Trip totals unavailable" message when both absent
  • Analytics: Deferred to follow-up (TODO marker), since no existing event tracks summary display
