User Story

1.4.1 — Loading Feedback for DB Operations

As a user, I want to see a loading spinner and have action buttons disabled while any database operation is in progress, so that I know my action is being processed and I don't accidentally trigger duplicate or conflicting actions.

Branch

feature/1.4.1-dialog-loading-feedback created from main

Story Refinement Summary

The original story was well-scoped but lacked specific file-level guidance. The refined version adds:

  • ViewModel gap analysis: identified 5 operations in TripDetailViewModel missing isLoading wrapping (editStop, removeStop, moveStop, markStopDeparted, undoMarkStopDeparted); TripListViewModel is already complete.
  • Dialog changes: SetStopDialog and CreateTripDialog need an isLoading parameter, button disabling, and a CircularProgressIndicator.
  • Screen wiring: TripDetailScreen (4 dialog instances + action buttons) and TripListScreen (1 dialog instance) must pass isLoading through.
  • Comprehensive file list: 8 files to modify (2 ViewModels, 2 dialogs, 2 screens, 2 test files + 2 instrumented test files).
  • Non-functional analysis: security (double-submission prevention), performance (negligible), GDPR (no impact), accessibility (built-in TalkBack support).

Change Proposed

5 Jun 2026

Source: sdlc_propose

Exploration Findings

  • isLoading coverage gap: Only setStop() in TripDetailViewModel and createTrip() in TripListViewModel wrap with isLoading. Five operations (editStop, removeStop, moveStop, markStopDeparted, undoMarkStopDeparted) are missing.
  • UI wiring absent: Neither SetStopDialog nor CreateTripDialog accept an isLoading parameter. Neither screen passes the flag to composables. Buttons remain enabled during async operations.
  • StopSection design choice: Action buttons use nullable lambdas for show/hide. For loading state, adding an isLoading parameter to disable (not hide) buttons is preferred to avoid layout shift.
  • Test gap: No existing tests verify isLoading transitions for any operation in either ViewModel.

Questions and Clarifications

No clarifications needed — the story is precisely scoped with explicit file lists, acceptance criteria, and completion criteria.
