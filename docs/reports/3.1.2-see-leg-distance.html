User Story

3.1.2 — See Distance for Each Leg

Branch: feature/3.1.2-see-leg-distance

Refinement Summary

  • Built upon story 3.1.1 (calculate route between stops) — distance data already exists in the domain model and is persisted locally
  • Scoped to two incremental changes:
    1. Add imperial unit support (miles/feet) for distance display alongside metric (kilometres/metres)
    2. Display an unavailable indicator when distance data is not yet fetched or failed
  • No new domain model fields, database columns, or API calls required — all data is local
  • Only two files require changes: LegSummary.kt composable and string resource files (strings.xml and localisations)
  • No security, performance, or GDPR concerns identified

Definition of Done

  • Distance displays in metric units (km/m) by default
  • Distance displays in imperial units (miles/feet) when device locale is en-US or en-GB (region US)
  • Unavailable indicator displays when distance is null or zero
  • All string resources extracted to strings.xml with i18n translation keys
  • All existing strings updated in secondary language files
  • Unit display is localised (e.g. "2.5 km" in Italian locale, "1.56 mi" in US English)
  • Unit tests cover imperial/metric conversion and null/zero distance handling
  • Compose UI tests cover all LegSummary states (metric, imperial, unavailable)
  • Build completes successfully with no warnings

Proposal

21 Jun 2026

Source: propose_change

Exploration Summary

  • LegSummary.kt contains a private @Composable formatDistance() function with metric-only logic (metres/km). No imperial branch exists.
  • Leg.distanceMetres: Int is non-nullable — no concept of "unavailable distance" at the domain level.
  • TripDetailScreen conditionally renders LegSummary only when a Leg exists for a fromStopId.
  • No locale-detection utility exists anywhere in the codebase — this is the first locale-aware feature.
  • Spec drift found: route-display/spec.md documents a stale composable signature and duration format.

Questions and Answers

QuestionAnswer
Unavailable distance: show "---" placeholder or keep current hide behaviour? Keep current behaviour — hide LegSummary when no Leg exists. No domain model change.
Imperial locale detection API? Dual strategy: LocaleData.getMeasurementSystem() on API 28+, hardcoded country set (US, GB, LR, MM) fallback on API 24-27.
Where should the testable formatting function live? Same file (LegSummary.kt) as a top-level internal function.
Short imperial distances: feet or always miles? Always miles (e.g. "0.3 mi"). No feet threshold.

  • formatDistance extracted to non-@Composable internal function taking Locale parameter for unit testability

  • Spec drift in route-display reconciled: composable signature, duration format, and new imperial requirement
