Summary

User story 3.2.1 — See Total Distance of the Roadtrip opened for development on branch feature/PL013-3.2.1.

Refinement Highlights

  • Total distance is a derived value — sum of existing Leg.distanceMetres across all legs
  • No new persisted field required; no endpoint required
  • Proposed approach: pre-compute formattedTotalDistance: String? on TripDetailUiState, computed in ViewModel's existing legs collector
  • Reuses formatDistance(...) for consistency with existing formattedLegDistances and formattedLegDurations
  • Route availability model clarified: all-or-nothing invalidation (InvalidateRouteUseCase deletes all legs on any stop mutation)
  • Route is complete when legs.size == placedStopCount − 1 and placedStopCount >= 2; otherwise unavailable (no partial state)
  • Total lives on Trip Detail overview footer

Key Decisions

  • Summation accumulates as Long to guard against integer overflow
  • Total displays only when route is complete (legs available)
  • When route unavailable, total field remains null (no "unavailable" placeholder text)
  • Composable summation/formatting stays in ViewModel, not in UI layer

Scope & Assumptions

  • Trip list total deferred — trip list loads only stop count, no leg data; total distance on trip cards deferred as separate story
  • Partial routes with warning dropped — actual InvalidateRouteUseCase uses all-or-nothing semantics, not partial with warning
  • Total lives on Trip Detail, not trip list — aligns with available leg data at that screen

Change Proposed

6 Jul 2026

Source: sdlc_propose_change

Exploration Findings

  • Total distance is a purely derived value — sum of Leg.distanceMetres already present in TripDetailUiState.legs
  • No new domain model field needed; no new network call required
  • Existing DistanceFormatter.formatDistance can be reused as-is for consistent display
  • Route availability model clarified: all-or-nothing invalidation — any stop mutation deletes all legs (via existing InvalidateRouteUseCase)
  • Route completeness rule: legs.size == stops.size - 1 && stops.size >= 2; legs are either complete or absent (no partial state)
  • Every Stop is placed (lat/long non-nullable), so placedStopCount = stops.size
  • Existing composables LegSummary and TripProgressSummary provide the stateless pattern to mirror
  • Locale files values-es-rES and values-it both need new strings; values (EN) is primary source of truth
  • Existing createViewModel(stops, legs) test factory already supports new tests without modification

Decisions Resolved (Auto Mode, Per Story Assumptions)

  • UiState Design: Add only formattedTotalDistance: String? = null to TripDetailUiState. No separate isRouteComplete flag (unavailable state signalled by null + fallback string in render)
  • Computation: Add separate combine(observeStopsUseCase, observeLegsUseCase) collector for the total, leaving existing stops-only and legs-only collectors untouched (lower risk, preserves tested behaviour)
  • String Resources: trip_detail_total_distance_label = "Total distance", trip_detail_total_distance_unavailable = "Total distance unavailable"
  • UI Location: Total rendered as new LazyColumn item (TripTotalSummary) near the calculate-route button
  • Scope Boundaries: Trip-list total is OUT OF SCOPE (deferred as separate story). No new analytics events
