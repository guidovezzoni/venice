Summary

User story 3.2.1 — See Total Distance of the Roadtrip opened for development on branch feature/PL013-3.2.1.

Refinement Highlights

  • Total distance is a derived value — sum of existing Leg.distanceMetres across all legs
  • No new persisted field required; no endpoint required
  • Proposed approach: pre-compute formattedTotalDistance: String? on TripDetailUiState, computed in ViewModel's existing legs collector
  • Reuses formatDistance(...) for consistency with existing formattedLegDistances and formattedLegDurations
  • Route availability model clarified: all-or-nothing invalidation (InvalidateRouteUseCase deletes all legs on any stop mutation)
  • Route is complete when legs.size == placedStopCount − 1 and placedStopCount >= 2; otherwise unavailable (no partial state)
  • Total lives on Trip Detail overview footer

Key Decisions

  • Summation accumulates as Long to guard against integer overflow
  • Total displays only when route is complete (legs available)
  • When route unavailable, total field remains null (no "unavailable" placeholder text)
  • Composable summation/formatting stays in ViewModel, not in UI layer

Scope & Assumptions

  • Trip list total deferred — trip list loads only stop count, no leg data; total distance on trip cards deferred as separate story
  • Partial routes with warning dropped — actual InvalidateRouteUseCase uses all-or-nothing semantics, not partial with warning
  • Total lives on Trip Detail, not trip list — aligns with available leg data at that screen
