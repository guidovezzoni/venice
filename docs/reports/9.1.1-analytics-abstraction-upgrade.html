Summary

Story 9.1.1: Upgrade the Analytics Abstraction refines the structural requirements for the analytics layer ahead of the taxonomy implementation in stories 9.1.2 and 9.1.3. This is a foundational change moving all analytics code from scattered locations into a unified core/analytics/ package and establishing the contracts that will support both event taxonomy and user properties.

Branch

feature/9.1.1-analytics-abstraction-upgrade

Scope: What Moves and What Changes

  • Package relocation: all analytics code moves from domain/analytics/ and data/analytics/ to core/analytics/, following the cross-cutting-concerns charter in the Architecture guidelines
  • Shared tracking surface: new AnalyticsTracking interface declares logEvent(), setUserProperty(), and trackException() once, eliminating duplication across client and providers
  • Event and property taxonomy: AnalyticsEvent and AnalyticsUserProperty sealed classes hold the exhaustive list of trackable events and properties (populated in 9.1.2)
  • Exception channel: trackException(throwable, operation) separates diagnostic data (full stack trace to crash reporting) from product analytics (bounded enums only), preventing free text and identifiers leaking into the analytics pipeline
  • User property API: setUserProperty(property) is added to the tracking surface; its implementation is unused until story 9.1.2
  • Debug-only Logcat provider: DebugAnalyticsProvider binding moves to the debug source set via `@TestInstallIn`, preventing the unencrypted event stream from shipping in release builds
  • Naming alignment: method and class names updated to match Firebase SDK conventions (e.g. `logEvent` not `trackEvent`, `AnalyticsProvider` not `AnalyticsBackend`)
  • KDoc documentation: every public type receives full KDoc following the fakestore reference implementation style

Design Decisions

  1. Package destination: core/analytics/ with contracts and implementations together (not split)
  2. Shared AnalyticsTracking supertype to prevent drift between client and provider surfaces
  3. shouldTrack removed entirely — filtering folds into each provider's own logEvent
  4. AnalyticsOperation promoted to a typed enum with only the 7 existing values
  5. Debug-only registration via source-set DI binding, not a runtime BuildConfig flag
  6. Log formatting extracted to AnalyticsLogFormatter.kt for direct testability
