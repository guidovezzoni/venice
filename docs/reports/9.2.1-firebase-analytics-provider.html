Overview

User story 9.2.1 (Send Events to Firebase Analytics) was opened for development on the branch feature/9.2.1-firebase-analytics-provider, created from main.

Story Refinement

The story was enriched during opening with comprehensive analysis and implementation guidance:

  • Acceptance criteria expanded from 17 to 24 criteria with detailed Firebase provider specifications
  • Boolean-to-String handling for is_first_trip parameter aligned with tracking plan requirements
  • AD_ID permission removed from manifest — analytics provider does not require advertising identifier
  • Comprehensive GDPR analysis documented: consent is assumed granted pending story 9.3.1 (Settings + Consent Gate); this is a deliberate, recorded temporary position as noted in the tracking plan
  • Firebase console setup requirements identified:
    • Both development and production app IDs must be registered
    • All 14 custom event definitions must be registered as String dimensions (event-parameter names)
    • All integer parameters (stop_count, leg_count, suggestion_count, suggestion_position) must be registered as custom metrics
    • Both user properties (trip_count_band, distance_unit) must be registered as custom user properties
  • Unit testing strategy established: FirebaseAnalyticsProvider tested by mocking Firebase SDK; success and failure paths verified; thread-safety validated via concurrent dispatch from multiple coroutine contexts
  • Documentation update plan: tracking plan already lists Firebase as the target backend; no plan updates needed

Key Concerns and Decisions

  • Warning Consent gate is deferred: Story 9.3.1 must deliver the consent gate before any release ships to EU users. The consent assumption is recorded in the tracking plan and is monitored as a blocker.
  • Info US data processing: Firebase's US-based processing is acceptable for current scope; GDPR concerns are handled by the consent gate deferral.
  • Info AD_ID manifest merge: Confirmed that the provider does not add the AD_ID permission to the manifest.

Implementation Summary

All 69 tasks completed across 15 sections using sub-agent orchestration (5 Sonnet, 3 Haiku agents). One iteration cycle was required for the BDD sections due to Detekt rule violations encountered and resolved within the same sub-agent run.

What Was Applied

Section 1: Firebase Console Setup

Tasks 1.1–1.4 confirmed complete (Firebase project exists, both app IDs registered, google-services.json placed at app/google-services.json). Task 1.5 (GitHub secret GOOGLE_SERVICES_JSON_BASE64) requires user action in GitHub repo settings.

Section 2: Gradle & Dependencies

  • Firebase BOM 33.7.0 and firebase-analytics added to gradle/libs.versions.toml
  • Google Services plugin 4.4.2 added to version catalog and root build.gradle.kts
  • Plugin applied in app/build.gradle.kts with BOM platform + analytics implementation
  • google-services.json added to .gitignore
  • Missing-file guard (doFirst) added — fails with a clear, actionable error when google-services.json is absent (verified manually)
  • Dependency resolution confirmed: firebase-bom:33.7.0 and firebase-analytics:22.1.2 resolve via existing google() filter

Sections 3–9: FirebaseAnalyticsProvider (BDD)

19 unit tests written and passing in FirebaseAnalyticsProviderTest. Key implementation decisions:

  • Constructor-injected FirebaseAnalytics (via FirebaseModule) — fully unit-testable without Robolectric
  • Generic Bundle mapping: String→putString, Int/Long→putLong, Double→putDouble, Boolean→putString("true"/"false")
  • ScreenViewed special-cased to FirebaseAnalytics.Event.SCREEN_VIEW + SCREEN_NAME param
  • User properties mapped exhaustively via when on sealed interface
  • trackException is a documented no-op (Crashlytics is a future provider)
  • Platform-limit enforcement: event/param name ≤40 chars, String value ≤100 chars, ≤25 params, user property name ≤24 chars, reserved-prefix rejection; debug builds throw IllegalStateException, release builds log and drop
  • Thread-safe: no mutable instance state; documented in class KDoc

Notable issue resolved: internal fun validateAndSetUserProperty(name, value) exposed for testability, because the current taxonomy's mapped user property names are all well under 24 chars, making the validation unreachable via the public API. The KDoc explains the rationale.

Section 10: DI Wiring

@Binds @IntoSet added to AnalyticsModule binding FirebaseAnalyticsProvider as AnalyticsProvider. FirebaseModule provides FirebaseAnalytics.getInstance(context) and isDebugBuild: Boolean. DebugAnalyticsModule (debug source set) unchanged.

Section 11: Manifest

google_analytics_automatic_screen_reporting_enabled=false added to AndroidManifest.xml. AD_ID permission left as Firebase merge adds it (per design deviation from AC 19). All other Firebase automatic events reviewed and knowingly left enabled.

Section 12: CI/CD

"Set up Firebase config" step added to both ci.yml (after gradlew chmod) and deploy.yml (after local.properties setup), decoding GOOGLE_SERVICES_JSON_BASE64 secret to app/google-services.json.

Section 13: Documentation

Tracking plan updated with Autocapture section (screen_view disabled, other automatic events recorded as intentionally enabled). is_first_trip Boolean→String conversion noted in parameter reference. AGENTS.md completed stories list updated to include 9.2.1.

Section 14: Compliance

Privacy Policy reviewed and updated to explicitly name Firebase Analytics and US data processing. Play Data Safety form requirements noted: Analytics data sharing with Firebase/Google, device information collection, and AD_ID permission need to be declared in the Play Console.
