Change Proposal

18 August 2026

Source: sdlc:sdlc_propose_change

Exploration Findings

  • core/analytics/ carries 8 files from 9.1.1; AnalyticsEvent.kt has 10 legacy subtypes with raw IDs
  • AnalyticsOperation has 7 values, needs 3 more: UNDO_MARK_DEPARTED, SEARCH_PLACE, RESOLVE_PLACE
  • AnalyticsUserProperty has only a ForTesting placeholder
  • Both ViewModels already inject AnalyticsClient; domain models carry all data needed for new parameters
  • TripListViewModel has no leg/route data; InvalidateRouteUseCase deletes legs (no stale state)
  • DirectionsApiService throws generic IllegalStateException with no structured status code
  • VeniceApplication has no AnalyticsClient injection yet

Design Questions and Resolutions

QuestionResolution
route_state for trip_opened — no data in TripListViewModel, and stale is unreachable Move trip_opened to TripDetailViewModel.init where legs are observed. Accept none/complete only; document stale as unreachable.
Error classification — DirectionsApiService has no structured exceptions Classify by exception type only: SocketTimeoutException → timeout, IOException → network, SQLiteException → persistence, else unknown. Defer finer classification.
route_calculated banding — raw totals unavailable in calculateRoute() Change CalculateRouteUseCase return type to Result<List<Leg>>. Small, well-scoped domain change.
stop_position sourcing for departure events Change MarkStopDepartedUseCase and UndoMarkStopDepartedUseCase to return Result<Stop>.

Key Design Decisions

  1. 6 new enum files + AnalyticsOperation extended; direction/route_state stay as inline strings (no dedicated enums)
  2. Error classification by exception type only — conservative, correct, deferring message parsing
  3. 3 domain return-type changes: RouteRepository.calculateRoute → Result<List<Leg>>, MarkStopDepartedUseCase → Result<Stop>, UndoMarkStopDepartedUseCase → Result<Stop>
  4. trip_opened fires once from TripDetailViewModel.init via .take(1) on a separate combine block
  5. Dual-channel failure emission: classify once, then logEvent + trackException in the same onFailure block
  6. distance_unit set immediately after super.onCreate() in VeniceApplication, before Places SDK init
  7. AnalyticsLogFormatter needs no code changes — operates generically
