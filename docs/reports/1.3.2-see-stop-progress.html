User Story

1.3.2 — See Which Stops Are Upcoming vs Completed

As a user, I want to see which stops are upcoming vs completed so that I can understand where I am in my roadtrip at a glance.

Branch

feature/1.3.2-see-stop-progress created from main

Refinement Summary

  • Analysed the existing 1.3.1 implementation: StopDisplayState enum, deriveDisplayState(), and basic alpha/tint styling already in place.
  • Identified three gaps: no checkmark icon for departed stops, no card highlight for current stop, and no progress summary indicator.
  • Defined 6 specific acceptance criteria covering departed/current/upcoming visual states and the progress summary for all edge cases (0/N, partial, N/N).
  • Designed a new TripProgressSummary composable with LinearProgressIndicator.
  • Planned modifications to StopSection (checkmark icon, primary border) and TripDetailScreen (progress computation and display).
  • No data or domain layer changes required — purely UI story.

Change Proposed

4 June 2026

Source: opsx:propose

Exploration Findings

  • StopDisplayState (DEPARTED/CURRENT/UPCOMING) and deriveDisplayState() are fully functional from 1.3.1.
  • StopSection already accepts stopDisplayState and applies alpha (0.6f) for departed and primary icon tint for current.
  • The icon parameter is caller-provided — override inside FilledStop is the cleanest approach for the checkmark swap.
  • TripDetailScreen already assembles allStops and computes currentStopId / lastDepartedStopId — progress counts can derive from the same list.
  • No isolated StopSectionTest exists — tests for new stop visual states will be created.
  • Three locales need updating: en (default), it, es-ES.
