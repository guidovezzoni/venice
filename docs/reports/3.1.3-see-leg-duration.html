Summary

User story 3.1.3 — See Estimated Duration for Each Leg opened for development on branch feature/3.1.3-see-leg-duration-v2.

Refinement Highlights

  • Identified this as primarily an architectural refactoring — duration is already displayed, but formatting logic lives inside the composable (violating project conventions)
  • Scoped the work to: extract duration formatting into a testable utility, pre-compute in ViewModel, pass as string parameter to LegSummary
  • Follows the same pattern already established by DistanceFormatter.kt and formattedLegDistances
  • New UiState field: formattedLegDurations: Map<String, String>
  • No database changes, no API calls, no new string resources needed

Key Decisions

  • Seconds-to-minutes conversion uses truncation (integer division), not rounding
  • Format: "X min" for sub-hour, "Xh Ymin" for 60+ minutes
  • Zero-second duration displays as "0 min"
  • No locale dependency for duration formatting (time units are universal)
  • No unavailable-duration placeholder needed (LegSummary only renders when leg exists)

Concerns

None No security, performance, or GDPR concerns identified. This is a pure UI-layer refactoring.
